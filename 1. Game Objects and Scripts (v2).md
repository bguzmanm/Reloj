 # Game Objects and Scripts

> **Versión 2 — actualizada a Unity 6 (URP).** La guía original se creó con Unity 2020.3.6f1 y muchos pasos de interfaz han cambiado desde entonces. Esta versión 2 adapta el tutorial a las versiones actuales; el código C# es exactamente el mismo y sigue funcionando sin cambios.

Este es el primer tutorial de una serie sobre los [[Basics.base|fundamentos]] del trabajo con Unity. En él, crearemos un reloj sencillo y programaremos un componente para que muestre la hora actual. No es necesario tener experiencia previa con el editor de Unity, pero se presupone que tienes cierta experiencia con aplicaciones de edición con múltiples ventanas en general.

Esta versión está probada con **Unity 6.3 LTS (6000.3.x)**, la versión de soporte a largo plazo actual (septiembre de 2026). Los pasos son idénticos en cualquier versión de Unity 6 (6.0, 6.1, 6.2, 6.5 y posteriores); si la tuya es distinta, puede que algún menú esté en un lugar ligeramente diferente, pero los conceptos no cambian.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/tutorial-image.jpg)

Es tiempo de crear un reloj.

> **Nota sobre las capturas de pantalla:** las imágenes de este tutorial proceden de la versión original de Catlike Coding (hechas con Unity 2020). La disposición de ventanas y los conceptos siguen siendo los mismos en Unity 6; cuando la interfaz actual difiera de forma relevante, lo indico en el texto.

## Cambios principales respecto a la versión 1

| Tema | Versión 1 (Unity 2020) | Versión 2 (Unity 6) |
| --- | --- | --- |
| Versión de Unity | 2020.3.6f1 | Unity 6.3 LTS (6000.3.x) — vale cualquier Unity 6.x |
| Plantilla de proyecto | 3D estándar (Built-In RP) | **Universal 3D** (URP). La Built-In RP está deprecada desde Unity 6.5 y Unity avisa al crear proyectos con ella |
| Espacio de color | Había que cambiar de gamma a lineal a mano | Ya es **lineal por defecto** con la plantilla Universal 3D; no hay que hacer nada |
| Paquetes | Eliminar todos excepto Visual Studio Editor | Conservar **Universal RP** (obligatorio) y el paquete de tu editor de código; el resto es opcional |
| Package Manager | *Window / Package Manager*, con *Show Dependencies* | *Window / Package Management / Package Manager*, con panel de navegación; *Show Dependencies* ya no existe |
| Escena de ejemplo | Main Camera + Directional Light | Main Camera + Directional Light + **Global Volume** (post-procesado) |
| Materiales | Propiedad *Albedo* (shader Standard) | **Base Map** en la sección *Surface Inputs* (shader Universal Render Pipeline/Lit) |
| Capturas | UI de Unity 2020 | Se conservan las originales, con notas donde la UI cambia |

## Creando un Proyecto

Antes de poder empezar a trabajar con el editor de Unity, primero debemos crear un proyecto.

### Nuevo Proyecto

Al abrir Unity, verás el Unity Hub. Esta es una aplicación de inicio e instalación desde donde puedes crear o abrir proyectos, instalar versiones de Unity y realizar otras acciones. Si no tienes una versión de Unity 6 instalada, añádela ahora desde la pestaña *Installs* / *Add* del Hub (te recomiendo la última **LTS**, por ejemplo **Unity 6.3 LTS**; cualquier versión 6.x sirve para este tutorial).

Al crear un nuevo proyecto (botón *New project*), el flujo es el siguiente en las versiones recientes del Hub:

1. Elige la **versión del editor** (se preselecciona la última LTS instalada).
2. Elige una **plantilla** de entre las tarjetas que se muestran. Usaremos **Universal 3D**, que es la recomendada: configura el proyecto con la *Universal Render Pipeline* (URP), el render pipeline moderno de Unity.
   - No elijas la plantilla *3D (Built-In Render Pipeline)*: Unity está deprecando la *Built-In Render Pipeline* (de forma oficial desde Unity 6.5) y muestra avisos al usarla en proyectos nuevos. Para un proyecto que empieces hoy, *Universal 3D* es la elección correcta.
3. Ponle nombre al proyecto y elige dónde guardarlo. Si aparece la casilla *Use Unity CLI*, déjala desmarcada (solo la necesitas si piensas automatizar el proyecto desde la línea de comandos).
4. Pulsa *Create project*. El proyecto se añade a la lista y se abre en la versión correspondiente del editor de Unity.

### Diseño del editor

Si aún no has personalizado el editor, se utilizará el diseño de ventana predeterminado.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/default-layout.png)

Diseño predeterminado del editor (captura de la guía original; el de Unity 6 mantiene la misma disposición general).

El diseño predeterminado incluye todas las ventanas necesarias, pero puedes personalizarlo a tu gusto, reordenándolas y agrupándolas. También puedes abrir y cerrar ventanas, como en la tienda de recursos. Cada ventana tiene sus propias opciones de configuración, accesibles mediante el botón de tres puntos en la esquina superior derecha. Además, la mayoría cuenta con una barra de herramientas con más opciones. Si tu ventana no se ve igual que en los tutoriales (por ejemplo, si la ventana de escena tiene un fondo uniforme en lugar de un skybox), significa que alguna de sus opciones es diferente.

Puedes cambiar a un diseño preconfigurado mediante el menú desplegable en la esquina superior derecha del editor de Unity. También puedes guardar tu diseño actual para recuperarlo más tarde.

### Packages

La funcionalidad de Unity es modular. Además de las funciones básicas, existen paquetes adicionales que se pueden descargar e incluir en tu proyecto. El proyecto creado con la plantilla *Universal 3D* incluye varios paquetes, que puedes ver en la ventana del proyecto, en la sección *Packages*.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/default-packages.png)

Paquetes del proyecto en Unity 2020 (las capturas originales muestran menos paquetes; en Unity 6 la plantilla Universal 3D trae más: *Universal RP*, *Visual Scripting*, *Timeline*, *Test Framework*, *Input System*, etc.).

Estos paquetes se pueden ocultar activando el botón con forma de ojo tachado, situado en la esquina superior derecha de la ventana del proyecto. Esto sirve para reducir el desorden visual en el editor; los paquetes siguen formando parte del proyecto. El botón también muestra cuántos paquetes de este tipo hay.

Puedes controlar qué paquetes se incluyen en tu proyecto mediante el gestor de paquetes, al que puedes acceder desde el menú **Window / Package Management / Package Manager** (en Unity 2020 el menú se llamaba *Window / Package Manager*).

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/package-manager.png)
Administrador de paquetes en Unity 2020. En Unity 6 la ventana tiene un panel de navegación a la izquierda con contextos como *In Project*, *Unity Registry*, *My Assets* y *Built-in*.

Los paquetes añaden funcionalidades adicionales a Unity. Por ejemplo, *Visual Studio Editor* integra el editor Visual Studio, utilizado para escribir código. Si utilizas otro editor (Rider, VS Code, etc.), deberás incluir su paquete de integración, si existe.

**Importante (cambio respecto a la versión original):** en Unity 2020 el tutorial pedía eliminar todos los paquetes excepto *Visual Studio Editor* para reducir el desorden. Con la plantilla Universal 3D eso ya no se recomienda: el paquete **Universal RP** es necesario para que el proyecto renderice correctamente (si lo eliminas, los materiales se verán de color magenta). Conserva *Universal RP* y el paquete de tu editor de código, y no pasa nada por dejar el resto. Si quieres un proyecto más limpio, puedes eliminar los que no uses (por ejemplo *Visual Scripting*, *Timeline*, *Test Framework* o *Multiplayer Center* si aparece): selecciónalos uno a uno en la lista y usa el botón *Remove* (o el menú *Manage / Remove*) del panel de detalles, en la esquina inferior derecha de la ventana. Unity recompilará después de cada eliminación, por lo que el proceso tarda unos segundos en finalizar.

En Unity 6 la opción *Show Dependencies* del administrador de paquetes **ya no existe** (en la versión original servía para hacer visibles los paquetes dependientes). Ahora las dependencias de cada paquete se muestran directamente en su panel de detalles, en la sección *Dependencies*.

### Color Space

> **Cambio importante respecto a la versión 1:** ya no hay que hacer nada aquí.

En la guía original había que cambiar el espacio de color de gamma a lineal manualmente, porque la plantilla 3D clásica estaba configurada con gamma por defecto. En las plantillas modernas de Unity 6 (incluida *Universal 3D*) el espacio de color **ya es lineal por defecto**, así que puedes saltarte este paso sin preocuparte.

(Si por alguna razón usaras la plantilla *3D (Built-In Render Pipeline)*, esa sí sigue configurada con gamma por defecto y deberías cambiarla a mano: *Edit / Project Settings...*, categoría *Player*, panel *Other Settings*, sección *Rendering*, *Color Space* → *Linear*. Unity mostrará una advertencia indicando que esto podría tardar bastante, pero no será el caso en un proyecto casi vacío.)

### Escena de ejemplo

El nuevo proyecto contiene una escena de ejemplo llamada *SampleScene*, que se abre por defecto. Puedes encontrarla en *Assets / Scenes* en la ventana del proyecto.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/two-column-layout.png)

Escena de ejemplo en la ventana del proyecto (captura de la guía original).

Por defecto, la ventana del proyecto utiliza un diseño de dos columnas. Puede cambiar a un diseño de una columna mediante la opción de configuración de tres puntos.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/one-column-layout.png)

Diseño de una columna.

La escena de ejemplo contiene una cámara principal y una luz direccional. Además, la plantilla Universal 3D añade un objeto **Global Volume**, que controla el post-procesado de la escena (efectos de cámara como el desenfoque o el *bloom*). Estos son objetos del juego. Se muestran en la ventana de jerarquía, debajo de la escena.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/sample-scene-hierarchy.png)

Jerarquía de objetos dentro de la escena (la captura original solo muestra cámara y luz; en Unity 6 aparece además *Global Volume*).

Puedes seleccionar un objeto del juego tanto en la ventana de jerarquía como en la ventana de escena. La cámara tiene un icono de escena que se asemeja a una cámara de cine antigua, mientras que el icono de la luz direccional se asemeja a un sol.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/creating-a-project/scene-icons.png)

Iconos en la ventana de escena.

No será necesario modificar la cámara, la luz ni el *Global Volume*, así que podemos ocultarlos en la escena haciendo clic en el icono del ojo a su izquierda en la ventana de jerarquía. Este icono está invisible por defecto, pero aparecerá al pasar el cursor sobre él. Esto sirve simplemente para reducir el desorden visual en la ventana de escena.

## Construyendo un reloj sencillo

Ahora que nuestro proyecto está configurado correctamente, podemos empezar a crear nuestro reloj.

### Creación de un objeto de juego

Necesitamos un objeto de juego para representar el reloj. Empezaremos con el objeto de juego más simple posible: uno vacío. Se puede crear mediante la opción de menú *GameObject / Create Empty* (en las versiones recientes también puedes usar el botón **+** de la parte superior de la ventana de jerarquía, o el menú contextual de esa ventana, que se abre con un clic alternativo, normalmente con el botón derecho o pulsando con dos dedos). Esto añadirá el objeto de juego a la escena. Aparecerá visible y seleccionado inmediatamente en la ventana de jerarquía, en *SampleScene*, que ahora está marcado con un asterisco para indicar que tiene cambios sin guardar. Puedes cambiarle el nombre inmediatamente o dejarlo para más adelante.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/new-game-object.png)

Jerarquía con el nuevo objeto de juego seleccionado.

La ventana del inspector muestra los detalles del objeto de juego mientras esté seleccionado. En la parte superior, aparece un encabezado con el nombre del objeto y algunas opciones de configuración. Por defecto, el objeto está habilitado, no es estático, no tiene etiquetas y se encuentra en la capa predeterminada. Esta configuración es correcta, excepto por el nombre. Cámbiele el nombre a *Clock*.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/inspector.png)

Ventana del inspector con el reloj seleccionado.

Debajo del encabezado se muestra una lista de todos los componentes del objeto de juego. La lista siempre incluye un componente `Transform` en la parte superior, que es el único componente que tiene nuestro reloj actualmente. Este componente controla la posición, la rotación y la escala del objeto de juego. Asegúrate de que todos los valores de posición y rotación del reloj estén configurados en 0. Su escala debe ser uniformemente 1.

Como el objeto de juego está vacío, no es visible en la ventana de escena. Sin embargo, se puede ver una herramienta de manipulación en la ubicación del objeto de juego, que se encuentra en el centro del mundo.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/move-tool.png)

Seleccionado con la herramienta Mover.

La herramienta de manipulación activa se controla mediante los botones situados en la esquina superior izquierda de la barra de herramientas del editor. Los modos también se activan con las teclas Q, W, E, R, T e Y. El botón situado más a la derecha del grupo sirve para habilitar herramientas de edición personalizadas, que no están disponibles. La herramienta Mover está activa por defecto.

Junto a los botones de modo, hay tres botones más para controlar la posición, la orientación y el ajuste de las herramientas de manipulación.

### Creando la esfera del reloj

Aunque tenemos un objeto de reloj, aún no vemos nada. Tendremos que añadirle modelos 3D para que se renderice. Unity incluye algunos objetos primitivos que podemos usar para construir un reloj sencillo. Empecemos añadiendo un cilindro a la escena mediante *GameObject / 3D Object / Cylinder*. Asegúrate de que tenga los mismos valores de `Transform` que nuestro reloj.

![scene](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-scene.png)

Objeto de juego que representa un cilindro.

El nuevo objeto tiene tres componentes más que un objeto de juego vacío. En primer lugar, tiene un `MeshFilter`, que contiene una referencia a la malla cilíndrica integrada.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/mesh-filter.png)

Componente MeshFilter, configurado como cilindro.

El segundo componente es un `MeshRenderer`. Su función es asegurar que la malla del objeto se renderice. También determina el material que se utiliza para el renderizado, que es el material predeterminado. Este material también se muestra en el inspector, debajo de la lista de componentes.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/mesh-renderer.png)

Componente MeshRenderer, configurado con el material predeterminado.

El tercer componente es un `CapsuleCollider`, que se utiliza para la física 3D. El objeto representa un cilindro, pero tiene un colisionador de cápsula porque Unity no incluye un colisionador de cilindro primitivo. No lo necesitamos, así que podemos eliminar este componente. Si deseas usar física con tu reloj, es mejor usar un componente `MeshCollider`. Los componentes se pueden eliminar mediante el menú desplegable de tres puntos en la esquina superior derecha (en Unity 6, el menú contextual del componente).

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-without-collider.png)

Cilindro sin colisionador.

Transformaremos el cilindro en la esfera del reloj aplanándolo. Esto se logra disminuyendo la componente Y de su escala. Reduzcámosla a 0.2. Como la malla del cilindro tiene dos unidades de altura, su altura efectiva se convierte en 0.4 unidades. También crearemos un reloj grande, así que aumentaremos las componentes X y Z de su escala a 10.

![scene](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-scaled-scene.png)

Cilindro a escala.

Nuestro reloj debe colocarse de pie o colgarse en la pared, pero su esfera está actualmente plana. Podemos solucionarlo girando el cilindro un cuarto de vuelta. En Unity, el eje X apunta a la derecha, el eje Y hacia arriba y el eje Z hacia adelante. Así que diseñemos nuestro reloj con la misma orientación, de modo que veamos su parte frontal al observarlo a lo largo del eje Z. Ajusta la rotación del cilindro en el eje X a 90 grados y modifica la vista de la escena para que la parte frontal del reloj sea visible, de manera que la flecha azul del eje Z de la herramienta de mover apunte hacia afuera, hacia el interior de la pantalla.

![scene](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/cylinder-rotated-scene.png)

Cilindro girado.

Cambia el nombre del objeto cilindro a *Face*, ya que representa la esfera del reloj. Como es solo una parte del reloj, lo convertimos en un objeto hijo del objeto *Clock*. Para ello, arrastra la cara sobre el reloj en la ventana de jerarquía.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/child-object.png)

Objeto hijo Cara.

Los objetos hijos están sujetos a la transformación de su objeto padre. Esto significa que cuando *Clock* cambia de posición, *Face* también lo hace. Es como si fueran una sola entidad. Lo mismo ocurre con la rotación y la escala. Puedes usar esto para crear jerarquías de objetos complejas.

### Creación del perímetro del reloj

El anillo exterior de la esfera de un reloj suele tener marcas que indican la hora. Esto se conoce como el perímetro del reloj. Usaremos bloques para indicar las horas de un reloj de 12 horas.

Añade un cubo a la escena mediante *GameObject / 3D Object / Cube*, nómbralo *Hour Indicator 12* y conviértelo en hijo de *Clock*. El orden de los objetos hijos en la jerarquía no importa; puedes colocarlo encima o debajo de la esfera.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicator-child.png)

Objeto secundario indicador de hora.

Establece su escala X en 0.5, su escala Y en 1 y su escala Z en 0.1 para que se convierta en un bloque alargado, plano y estrecho. Luego, establece su posición X en 0, su posición Y en 4 y su posición Z en -0.25. Esto lo coloca sobre la esfera para indicar las 12. Elimina también su componente `BoxCollider`.

![scene](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/indicator-scene.png)

Indicador de la hora 12.

El indicador es difícil de ver porque tiene el mismo color que la esfera. Creemos un material aparte para él, a través de *Assets / Create / Material*, o mediante el botón de signo más o el menú contextual de la ventana del proyecto. Esto nos dará un recurso de material que es una copia del material predeterminado del proyecto. Cámbiale el nombre a *Hour Indicator*.

![one-column](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/material-project-one-column.png)

Indicador de hora en la ventana del proyecto, diseño de una o dos columnas.

> **Cambio respecto a la versión 1 (materiales):** en un proyecto URP, el material se crea con el shader *Universal Render Pipeline / Lit* y las propiedades se organizan en secciones. El color principal ya no se llama *Albedo*: ahora está en la sección **Surface Inputs**, en la propiedad **Base Map**. El resto del procedimiento es idéntico.

Seleccione el material y cambie su **Base Map** haciendo clic en su campo de color (en la captura original, *Albedo*). Esto abrirá una ventana emergente con varias opciones para elegir un color. Elegí gris oscuro, que corresponde al valor hexadecimal 494949, el mismo que el color uniforme 73 para el modo RGB 0-255. Como no usamos transparencia (el *Surface Type* de URP es *Opaque* por defecto), el valor del canal alfa es irrelevante. Podemos dejar las demás propiedades del material como están.

![color popup](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicator-material.png)

Base Map gris oscuro (captura original: propiedad *Albedo*).

Aplica este material al indicador de hora. Puedes hacerlo arrastrando el material al objeto en la ventana de escena o jerarquía. También puedes arrastrarlo a la parte inferior de la ventana del inspector cuando el objeto indicador esté seleccionado, o modificar el *Element 0* del array *Materials* de su `MeshRenderer`.

![scene](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/dark-hour-indicator-scene.png)

Indicador de hora oscura.

> **Nota:** como el proyecto ahora usa URP con espacio de color lineal y una luz direccional, los colores pueden verse ligeramente distintos en pantalla que en las capturas, pero los valores hexadecimales funcionan igual.

### Indicadores de doce horas

Podríamos usar un solo indicador para la hora 12, pero incluyamos uno para cada hora. Para empezar, orienta la cámara de la vista de escena de modo que apunte directamente al eje Z. Puedes hacerlo haciendo clic en los conos del eje del manipulador de la cámara en la esquina superior derecha de la vista de escena. También puedes cambiar el eje de la cuadrícula de escena al eje Z mediante el botón de la barra de herramientas de la cuadrícula.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/looking-along-z-axis.png)

Mirando directamente al reloj, a lo largo del eje Z.

Duplica el objeto de juego *Indicador de hora 12*. Puedes hacerlo mediante *Edit / Duplicate*, con el atajo de teclado indicado (o a través de su menú contextual en la ventana de jerarquía). El duplicado aparecerá debajo del original en la ventana de jerarquía, también como hijo de *Clock*. Su nombre es *Hour Indicator 12 (1)*. Cámbiale el nombre a *Hour Indicator 6* e invierte la componente Y de su posición para que indique la hora 6.

![hierarchy](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicator-6-hierarchy.png)

Indicadores para las horas 6 y 12.

Crea indicadores para las horas 3 y 9 de la misma forma. En este caso, sus posiciones X deberían ser 4 y −4, mientras que sus posiciones Y deberían ser cero. Además, establezca su rotación Z en 90 para que giren un cuarto de círculo.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/four-hour-indicators.png)

Indicadores de cuatro horas.

Luego cree otro duplicado del *Indicador de hora 12*, esta vez para la hora 1. Establezca su posición X en 2, su posición Y en 3,464 y su rotación Z en −30. Luego duplique ese para la hora 2, intercambie sus posiciones X e Y y duplique su rotación Z a −60.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/building-a-simple-clock/hour-indicators-1-2.png)

Indicadores de las horas 1 y 2.

Duplica estos dos indicadores y niega sus posiciones Y y sus rotaciones para crear los indicadores para las horas 4 y 5. Luego usa el mismo truco en las horas 1, 2, 4 y 5 para crear los indicadores restantes, esta vez negando sus posiciones X y nuevamente sus rotaciones.

### Definición de un tipo de componente

Una vez que el script esté cargado en su editor de código, comience eliminando el código de la plantilla estándar, ya que crearemos el tipo de componente desde cero.

Un archivo vacío no define nada. Debe contener la definición de nuestro componente de reloj. Lo que vamos a definir no es una única instancia de un componente. En su lugar, definimos la clase o tipo general conocido como **`Reloj`**. Una vez establecido esto, podremos crear múltiples componentes de este tipo en Unity, aunque nos limitaremos a un solo reloj en este tutorial.

En C#, definimos el tipo **`Reloj`** indicando primero que estamos definiendo una clase, seguido de su nombre. En los fragmentos de código a continuación, el código modificado tiene un fondo amarillo o rojo oscuro si está utilizando el tema de página web oscura para ver este tutorial. Como comenzamos con un archivo vacío, su contenido debería convertirse literalmente en **`class Clock`** y nada más, aunque puedes agregar espacios y nuevas líneas entre palabras como quieras.

```c#
class Clock
```

Debido a que no queremos restringir qué código tiene acceso a nuestro tipo **`Clock`**, es una buena idea anteponerle el modificador de acceso **`public`**.

```c#
public class Clock
```

En este punto todavía no tenemos una sintaxis C# válida. Si guardara el archivo y volviera al editor de Unity, los errores de compilación se registrarán en la ventana de su consola.

Indicamos que estamos definiendo un tipo, por lo que debemos definir cómo es. Esto se hace mediante un bloque de código que sigue a la declaración. Los límites de un bloque de código se indican entre llaves. Lo dejaremos vacío por ahora, así que simplemente escribe `{}`.

```c#
public class Clock {}
```

Nuestro código ahora es válido. Guarde el archivo y vuelva a Unity. El editor de Unity detectará que el activo del script ha cambiado y activará una recompilación. Una vez hecho esto, seleccione nuestro script. El inspector nos informará que el activo no contiene un script `MonoBehaviour`.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/non-component.png)

Guión sin componentes.

Lo que esto significa es que no podemos usar este script para crear componentes en Unity. En este punto, nuestro **`Clock`** define un tipo de objeto básico de C#. Nuestro tipo de componente personalizado debe extender el tipo `MonoBehaviour` de Unity, heredando sus datos y funcionalidad.

Para convertir **`Clock`** en un subtipo de `MonoBehaviour`, tenemos que cambiar nuestra declaración de tipo para que extienda ese tipo, lo cual se hace con dos puntos después de nuestro nombre de tipo, seguido de lo que extiende. Esto hace que **`Clock`** herede todo lo del tipo de clase `MonoBehaviour`.

```c#
public class Clock : MonoBehaviour {}
```

Sin embargo, esto generará un error después de la compilación. El compilador se queja de que no puede encontrar el tipo `MonoBehaviour`. Esto sucede porque el tipo está contenido en un espacio de nombres, que es `UnityEngine`. Para acceder a él, debemos usar su nombre completo, `UnityEngine.MonoBehaviour`.

```c#
public class Clock : UnityEngine.MonoBehaviour {}
```

Es inconveniente tener que incluir siempre el prefijo `UnityEngine` al acceder a los tipos de Unity. Afortunadamente, podemos declarar que el espacio de nombres debe buscarse automáticamente para completar los nombres de tipos en el archivo C#. Esto se hace agregando `using UnityEngine;` en la parte superior del archivo. Se requiere el punto y coma para marcar el final de la declaración.

```c#
using UnityEngine;

public class Clock : MonoBehaviour {}
```

Ahora podemos agregar nuestro componente personalizado al objeto del juego *Clock* en Unity. Esto se puede hacer arrastrando el activo del script al objeto o mediante el botón *Add Component* en la parte inferior del inspector del objeto.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/clock-with-component.png)

Objeto de juego Clock con nuestro componente Clock.

Tenga en cuenta que la mayoría de los tipos de código de mis tutoriales están vinculados a documentación en línea. Por ejemplo, `MonoBehaviour` es un enlace que lo lleva a la página API de secuencias de comandos en línea de Unity para ese tipo.

### Agarrando un brazo

Para rotar los brazos, los objetos **`Clock`** deben conocerlos. Empecemos con el brazo de horas. Como todos los objetos del juego, se puede rotar ajustando su componente `Transform`. Así que tenemos que agregar conocimiento del componente `Transform` del pivote del brazo a **`Clock`**. Esto se puede hacer agregando un campo de datos dentro de su bloque de código, definido como un nombre seguido de un punto y coma.

El nombre `hours pivot` sería apropiado para el campo. Sin embargo, los nombres tienen que ser palabras únicas. La convención es poner la primera palabra de un nombre de campo en minúscula y poner en mayúscula todas las demás palabras, luego unirlas. Entonces lo llamaremos `hoursPivot`.

```c#
public class Clock : MonoBehaviour {

    hoursPivot;
}
```

También tenemos que declarar el tipo de campo, que en este caso es `UnityEngine.Transform`. Debe escribirse delante del nombre del campo.

```c#
Transform hoursPivot;
```

Nuestra clase ahora define un campo que puede contener una referencia a otro objeto, cuyo tipo debe ser `Transform`. Tenemos que asegurarnos de que contenga una referencia al componente `Transform` del pivote del brazo de horas.

Los campos son privados de forma predeterminada, lo que significa que solo se puede acceder a ellos mediante el código que pertenece a `Clock`. Pero la clase no conoce nuestra escena de Unity, por lo que no hay una forma directa de asociar el campo con el objeto correcto. Podemos cambiar eso declarando el campo como serializable. Esto significa que debe incluirse en los datos de la escena cuando Unity guarda la escena, lo que hace poniendo todos los datos en una secuencia (seriazándolos) y escribiéndolos en un archivo.

Marcar un campo como serializable se realiza adjuntándole un atributo, en este caso `SerializeField`. Está escrito delante de la declaración de campo entre corchetes, normalmente en la línea superior, pero también se puede colocar en la misma línea.

```c#
[SerializeField]
Transform hoursPivot;
```

Una vez que el campo sea serializable, Unity lo detectará y lo mostrará en la ventana del inspector del componente **`Clock`** de nuestro objeto de juego *Reloj*.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/hours-pivot-field.png)

Campo dinámico de horas.

Para realizar la conexión adecuada, arrastre el *Pivote de brazo de horas* desde la jerarquía al campo *Pivote de horas*. Alternativamente, use el botón circular a la derecha del campo y busque el pivote en la lista que aparece. En ambos casos, el editor de Unity toma el componente `Transform` de *Hours Arm Pivot* y le pone una referencia en nuestro campo.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/hours-pivot-connected.png)

Pivote de horas conectado.

[SerializeField]
Transform hoursPivot, minutesPivot, secondsPivot;

//[SerializeField]
//Transform minutesPivot;

//[SerializeField]

### Despertar

Ahora que tenemos acceso a los pivotes del brazo, el siguiente paso es rotarlos. Para hacer esto, necesitamos decirle a **`Clock`** que ejecute algún código. Esto se hace agregando un bloque de código a la clase, conocido como método. El bloque debe tener como prefijo un nombre, que por convención está en mayúscula. Lo llamaremos `Awake`, sugiriendo que el código debe ejecutarse cuando el componente se despierte.

```c#
public class Clock : MonoBehaviour {

    [SerializeField]
    Transform hoursPivot, minutesPivot, secondsPivot;

    Awake {}
}
```

Los métodos son algo así como funciones matemáticas, por ejemplo $f(x)=2x+3$. Esa función toma un número, representado por el parámetro variable $x$, lo duplica y luego suma tres. Opera con un solo número y su resultado también es un solo número. En el caso de un método, es más como $f(p)=c$ donde $p$ representa los parámetros de entrada y $c$ representa cualquier código que ejecute.

Al igual que una función matemática, un método puede producir un resultado, pero esto no es necesario. Tenemos que declarar el tipo de resultado —como si fuera un campo— o escribir **`void`** para indicar que no hay resultado. En nuestro caso, solo queremos ejecutar algún código sin proporcionar un valor resultante, por eso usamos **`void`**.

```c#
void Awake {}
```

Tampoco necesitamos ningún dato de entrada. Sin embargo, todavía tenemos que definir los parámetros del método, como una lista separada por comas entre paréntesis. En nuestro caso es sólo una lista vacía.

```c#
void Awake () {}
```

Ahora tenemos un método válido, aunque todavía no hace nada. Así como Unity detectó nuestros campos, también detecta este método `Awake`. Cuando un componente tiene un método `Awake`, Unity invocará ese método en el componente cuando se despierte. Esto sucede después de que se haya creado o cargado en el modo de reproducción. Actualmente estamos en modo de edición, por lo que esto no sucede todavía.

Tenga en cuenta que `Awake` y otros métodos de eventos especiales de Unity tienen texto en negrita en mis tutoriales y enlaces a su página API de secuencias de comandos de Unity en línea.

### Rotación mediante código

Para rotar los brazos tenemos que crear una nueva rotación. Podemos cambiar la rotación de una `Transform` asignando una nueva a su propiedad `localRotation`.

Aunque la rotación de un componente `Transform` se define con ángulos de Euler en grados por eje en el inspector, en el código tenemos que hacerlo con un cuaternión.

Podemos crear un cuaternión basado en los ángulos de Euler invocando el método `Quaternion.Euler`. Haga esto escribiéndolo en `Awake`, seguido de un punto y coma para finalizar la declaración.

```c#
void Awake () {
    Quaternion.Euler;
}
```

El método tiene parámetros utilizados para describir la rotación deseada. En este caso, proporcionaremos una lista separada por comas que contiene tres argumentos, todos entre corchetes, después del nombre del método. Proporcionamos tres números para las rotaciones X, Y y Z. Utilice cero para los dos primeros y −30 para la rotación Z.

```c#
Quaternion.Euler(0, 0, -30);
```

El resultado de esta invocación es un valor de estructura `Quaternion` que contiene una rotación de 30° en el sentido de las agujas del reloj alrededor del eje Z, coincidiendo con la hora 1 de nuestro reloj.

Para aplicar esta rotación al brazo horario, asigne el resultado de `Quaternion.Euler` a `hoursPivots.localRotation`, usando la instrucción de asignación `=`.

```c#
hoursPivot.localRotation = Quaternion.Euler(0, 0, -30);
```

Ahora ingresa al modo de reproducción en el editor. Puedes hacerlo a través de *Edit / Play*, el método abreviado de teclado indicado, o presionando el botón de reproducción en la parte superior central de la ventana del editor. Unity cambiará el enfoque a la ventana del juego, que representa lo que ve la *Main Camera* en la escena. El componente del reloj se activará y el reloj se ajustará a la una.

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/one-o-clock.png)

Siempre la una en modo juego.

> **Nota:** como la escena ahora incluye un *Global Volume*, la imagen de la ventana de juego puede tener una ligera diferencia de color o de exposición respecto a la captura original. Es esperable y no afecta al ejercicio.

Si la cámara no está enfocada en el reloj, puedes moverla para que el reloj sea visible, pero ten en cuenta que la escena se reinicia al salir del modo de reproducción, por lo que cualquier cambio que realices en la escena mientras estás en el modo de reproducción no persistirá. Sin embargo, esto no es cierto para los activos, los cambios en ellos siempre persisten. También puedes tener la ventana de escena, o incluso varias ventanas de escena y juego, abiertas mientras estás en el modo de juego. Salga del modo de reproducción antes de continuar.

### Obteniendo la hora actual

El siguiente paso es averiguar la hora actual en la que despertamos. Podemos usar la estructura `DateTime` para acceder a la hora del sistema del dispositivo en el que estamos ejecutando. `DateTime` no es un tipo Unity, se encuentra en el espacio de nombres `System`. Es parte de la funcionalidad principal del marco .NET, que es lo que Unity utiliza para admitir secuencias de comandos.

`DateTime` tiene una propiedad `Now` que produce un valor `DateTime` que contiene la fecha y hora actuales del sistema. Para comprobar si es correcto, lo registraremos en la consola al comienzo de `Awake`. Podemos hacerlo pasándolo al método `Debug.Log`.

```c#
using System;
using UnityEngine;

public class Clock : MonoBehaviour {

    [SerializeField]
    Transform hoursPivot, minutesPivot, secondsPivot;

    void Awake () {
        Debug.Log(DateTime.Now);
        hoursPivot.localRotation = Quaternion.Euler(0, 0, -30);
    }
}
```

Ahora obtenemos una marca de tiempo registrada cada vez que ingresamos al modo de reproducción. Puedes verlo tanto en la ventana de la consola como en la barra de estado en la parte inferior de la ventana del editor.

### Girando los brazos

Nos estamos acercando a un reloj en funcionamiento. Empecemos de nuevo con las horas. `DateTime` tiene una propiedad `Hour` que nos proporciona la parte de horas de un valor `DateTime`. Invocarlo en la marca de tiempo actual nos dará la hora del día.

```c#
Debug.Log(DateTime.Now.Hour);
```

Entonces, para que el brazo de horas muestre la hora actual, tenemos que multiplicar la rotación de -30° por la hora actual. La multiplicación se realiza con el carácter asterisco `*`. Tampoco necesitamos registrar la hora actual para poder deshacernos de esa declaración.

```c#
//Debug.Log(DateTime.Now.Hour);
hoursPivot.localRotation = Quaternion.Euler(0, 0, -30 * DateTime.Now.Hour);
```

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/four-o-clock.png)

Actualmente son las cuatro en modo juego.

Para dejar claro que estamos convirtiendo de horas a grados, podemos definir un campo `hoursToDegrees` que contenga el factor de conversión. Los ángulos de `Quaternion.Euler` se definen como valores de punto flotante, por lo que usaremos el tipo **`float`**. Como ya conocemos el número, podemos asignarlo inmediatamente como parte de la declaración de campo. Luego multiplique con el campo en lugar del literal `-30` en `Awake`.

```c#
float hoursToDegrees = -30;

[SerializeField]
Transform hoursPivot, minutesPivot, secondsPivot;

void Awake () {
    hoursPivot.localRotation =
        Quaternion.Euler(0, 0, hoursToDegrees * DateTime.Now.Hour);
}
```

Si declaramos un número entero sin sufijo, se supone que es un número entero, que es un tipo de valor diferente. Aunque el compilador los convierte automáticamente, dejemos explícito que todos nuestros números son de tipo **`float`**, agregándoles el sufijo `f`.

```c#
float hoursToDegrees = -30f;

[SerializeField]
Transform hoursPivot, minutesPivot, secondsPivot;

void Awake () {
    hoursPivot.localRotation =
        Quaternion.Euler(0f, 0f, hoursToDegrees * DateTime.Now.Hour);
}
```

La cantidad de grados por hora es siempre la misma. Podemos hacer cumplir esto agregando el prefijo **`const`** a la declaración de `hoursToDegrees`. Esto lo convierte en una constante en lugar de un campo.

```c#
const float hoursToDegrees = -30f;
```

Demos el mismo tratamiento a los otros dos brazos, usando las propiedades apropiadas de `DateTime`. Tanto un minuto como un segundo están representados por una rotación de seis grados negativos.

```c#
const float hoursToDegrees = -30f, minutesToDegrees = -6f, secondsToDegrees = -6f;

[SerializeField]
Transform hoursPivot, minutesPivot, secondsPivot;

void Awake () {
    hoursPivot.localRotation =
        Quaternion.Euler(0f, 0f, hoursToDegrees * DateTime.Now.Hour);
    minutesPivot.localRotation =
        Quaternion.Euler(0f, 0f, minutesToDegrees * DateTime.Now.Minute);
    secondsPivot.localRotation =
        Quaternion.Euler(0f, 0f, secondsToDegrees * DateTime.Now.Second);
}
```

![](https://catlikecoding.com/unity/tutorials/basics/game-objects-and-scripts/animating-the-clock/time-5-16-31.png)

Actualmente 5:16:31.

Estamos usando `DateTime.Now` tres veces para recuperar la hora, los minutos y los segundos. Cada vez que volvemos a pasar por la propiedad, esto requiere algo de trabajo, lo que teóricamente podría resultar en diferentes valores de tiempo. Para asegurarnos de que esto no suceda, debemos recuperar la hora solo una vez. Podemos hacer esto declarando una variable dentro del método y asignándole el tiempo, y luego usar este valor. Llamémoslo `time`.

```c#
void Awake () {
    DateTime time = DateTime.Now;
    hoursPivot.localRotation =
        Quaternion.Euler(0f, 0f, hoursToDegrees * time.Hour);
    minutesPivot.localRotation =
        Quaternion.Euler(0f, 0f, minutesToDegrees * time.Minute);
    secondsPivot.localRotation =
        Quaternion.Euler(0f, 0f, secondsToDegrees * time.Second);
}
```

En el caso de una variable es posible omitir la declaración de tipo, reemplazándola con la palabra clave **`var`**. Esto puede acortar el código, pero sólo es posible cuando el tipo de variable se puede inferir de lo que se le asigna cuando se declara. Además, prefiero hacer esto solo cuando el tipo se menciona explícitamente en la declaración, como es el caso aquí.

```c#
var time = DateTime.Now;
```

### Animando los brazos

Obtenemos la hora actual al ingresar al modo de reproducción, pero luego el reloj permanece inmóvil. Para mantener el reloj sincronizado con la hora actual, cambie el nombre de nuestro método `Awake` a `Update`. Este es otro método de evento especial que Unity invoca en cada cuadro en lugar de solo una vez, siempre que permanezcamos en el modo de reproducción.

```c#
void Update () {
    var time = DateTime.Now;
    hoursPivot.localRotation =
        Quaternion.Euler(0f, 0f, hoursToDegrees * time.Hour);
    minutesPivot.localRotation =
        Quaternion.Euler(0f, 0f, minutesToDegrees * time.Minute);
    secondsPivot.localRotation =
        Quaternion.Euler(0f, 0f, secondsToDegrees * time.Second);
}
```

### Girando continuamente

Las manecillas de nuestro reloj indican exactamente la hora, minuto o segundo actual. Se comporta como un reloj digital, discreto pero con brazos. Normalmente los relojes tienen brazos que giran lentamente y proporcionan una representación analógica del tiempo. Cambiemos nuestro enfoque para que nuestro reloj se vuelva analógico.

`DateTime` no contiene datos fraccionarios. Afortunadamente, tiene una propiedad `TimeOfDay`. Esto nos da un valor `TimeSpan` que contiene los datos en el formato que necesitamos, a través de sus propiedades `TotalHours`, `TotalMinutes` y `TotalSeconds`.

Comience obteniendo el valor de la estructura `TimeOfDay` de `DateTime.Now` y guárdelo en la variable. Como el tipo `TimeSpan` no se menciona en esta declaración, haré explícito el tipo de variable. Luego ajusta las propiedades que usamos para rotar los brazos.

```c#
void Update () {
    TimeSpan time = DateTime.Now.TimeOfDay;
    hoursPivot.localRotation =
        Quaternion.Euler(0f, 0f, hoursToDegrees * time.TotalHours);
    minutesPivot.localRotation =
        Quaternion.Euler(0f, 0f, minutesToDegrees * time.TotalMinutes);
    secondsPivot.localRotation =
        Quaternion.Euler(0f, 0f, secondsToDegrees * time.TotalSeconds);
}
```

Esto resultará en errores del compilador, quejándonos de que no podemos convertir de **`double`** a **`float`**. Esto sucede porque las propiedades `TimeSpan` producen valores con el tipo de punto flotante de `double` precisión, conocido como **`double`**. Estos valores proporcionan mayor precisión que los valores `float`, pero el código de Unity solo funciona con valores de punto flotante de precisión simple.

Podemos resolver este problema convirtiendo explícitamente de **`double`** a **`float`**. Este proceso se conoce como conversión y se realiza escribiendo el nuevo tipo entre paréntesis delante del valor que se va a convertir.

```c#
hoursPivot.localRotation =
    Quaternion.Euler(0f, 0f, hoursToDegrees * (float)time.TotalHours);
minutesPivot.localRotation =
    Quaternion.Euler(0f, 0f, minutesToDegrees * (float)time.TotalMinutes);
secondsPivot.localRotation =
    Quaternion.Euler(0f, 0f, secondsToDegrees * (float)time.TotalSeconds);
```

## Resumen de cambios de la versión 2

Si vienes de la versión original (Unity 2020), esto es todo lo que ha cambiado:

- **Version de Unity:** del 2020.3.6f1 a **Unity 6.3 LTS (6000.3.x)**; los pasos valen para cualquier Unity 6.x.
- **Plantilla:** *3D estándar* → **Universal 3D** (URP). La *Built-In Render Pipeline* está deprecada (oficialmente desde Unity 6.5) y Unity muestra advertencias al usarla en proyectos nuevos; no la uses para empezar.
- **Espacio de color:** ya no hay que configurarlo; la plantilla URP usa espacio lineal por defecto.
- **Paquetes:** conserva **Universal RP** (imprescindible) y el paquete de tu editor de código; el resto puedes dejarlo o eliminarlo. La opción *Show Dependencies* ya no existe.
- **Package Manager:** se abre desde *Window / Package Management / Package Manager* y usa un panel de navegación en lugar del desplegable antiguo.
- **Escena de ejemplo:** además de cámara y luz, hay un objeto *Global Volume* (post-procesado); puedes ocultarlo con el icono del ojo.
- **Materiales:** la propiedad de color se llama **Base Map** (sección *Surface Inputs*, shader URP/Lit) en lugar de *Albedo*. Los valores hexadecimales de la guía (494949, 000000, B30000) funcionan igual.
- **Atajo de guardado:** en macOS es **Cmd + S** (**Ctrl + S** en Windows).
- **Código C#:** sin ningún cambio.
